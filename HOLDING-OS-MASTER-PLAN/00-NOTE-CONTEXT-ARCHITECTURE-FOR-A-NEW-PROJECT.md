# NOTE — how to give a NEW project its context architecture

## The one idea, and the thing it is NOT

It is not *"give the model less"*. Forty coherent pages harm nothing. What harms is **two pages
that contradict each other**, because the model spends its judgement resolving them instead of
doing the work.

> Give the smallest, highest-signal context, and let the rest be loaded when it is needed.

The measured proof from this project: the always-on text was 27 pages, and its defect was not
length — it was that one rule lived in 43 files and the copies had drifted apart until a rule the
CEO had given bound nobody.

So the engineering question is never *"how many pages"*. It is **"who owns this fact, and when
should it appear"**.

## Every project needs exactly four kinds of writing

Mixing them is the disease. Separate them on day one.

| | What it holds | The rule that keeps it honest |
|---|---|---|
| **The constitution** — always open, ONE page | what this project is · **who outranks whom** · the boundaries that never bend · which door to open for which job | If it changes weekly, the wrong things are in it |
| **The photograph** — ONE page | where the work stands right now | **Rewritten, never appended.** Ours became a 26-page narrative that contradicted itself in three places |
| **The open list** | everything unfinished | Exactly ONE list. The moment a second exists, both start lying |
| **The doors** | how to do a particular job | Never always-open. Loaded when that job arrives |

And a fifth that is not context at all: **the archive** — it answers *why was this decided*, and
must never be consulted for *where are we*.

## Three questions before any permanent instruction is written

1. **Can it be worked out by looking?** Then do not write it.
2. **Is it already written somewhere?** Then point at it — never copy it.
3. **Is it only needed for one kind of job?** Then it belongs in a door, not on the wall.

What survives all three is short, and it is read *because* it is short.

## The CEO's own test — five seconds, works on any project

He invented it on 2026-07-31 without meaning to, and it is now the acceptance test:

> **Open a fresh session. Say hello. Say nothing else.**
> - It tells you where the work stands → the architecture is right.
> - It asks *"what would you like me to do?"* → **it is wrong**, however good the rules read.

Run it on day one of a new project, and after any change to the always-on layer.

## Day one of a new project

1. **Write the one-page constitution before any code.** Not after.
2. **Write the authority order.** Its absence was the root of three weeks of contradiction here:
   nothing said which document outranked which.
3. **Create the photograph and the open list while they are still empty.** A list that is born
   later is always the second list.
4. **Do NOT write the doors on day one.** Write a door the *second* time you do that job. A
   procedure written before the need is a guess, and it will be wrong.
5. **Delete the second copy of a rule the moment you see it.** No exceptions.

## Two traps, both paid for in full on 2026-07-30/31

**A rule that is not obeyed does not need louder words — it needs a different place.** The reflex
is to write it again, harder. That reflex is what produced 27 pages. When the CEO's language rule
kept being broken, the wording was already correct; it was sitting behind a door that had to be
opened. Moving it to something that fires on every prompt fixed it, and nothing was rewritten.

**Measure what is loaded at the door, not only what you wrote.** The always-on text was cut from
27 pages to one — while a separate memory tool quietly loaded roughly 65 pages at every session
start, which nobody had ever measured because it was not our file. **The CEO found it, not the
author.** For any new project, the question is *"what does this session load in total"*, across
every tool, not *"what did I write"*.

## The opening order to hand a new project

Reusable as-is, with any model:

1. Before producing anything, write a one-page constitution: what this project is · which source
   outranks which when two disagree · the boundaries that never bend · which procedure is opened
   for which job.
2. Open two more: the **photograph** (one page, rewritten never appended) and the **open list**
   (one list).
3. Keep procedures out of the constitution. They live apart and are opened only when their job
   arrives.
4. Never write a rule twice. On seeing a second copy, delete it and point at the original.
5. **Every session's first reply states where the work stands, then answers what was asked.**
   Never ask the owner what to do.
6. Finished is not approved. Only the owner's own eye accepts.
7. A new order from the owner **deletes** whatever contradicts it — no footnote — and the report
   says what was deleted.
8. Measure what the session loads at startup **in total**, across all tools, and report it.

Six of those eight are the CEO's own rulings. They were only put in order.

## The number to aim at

This project went from roughly **54 pages before the owner's first word to about 6**, and **not one
rule was lost** — every one of them moved into a door.

For a new project, the target is: **the always-open text does not exceed one page.** If it does,
what exceeds it is almost certainly either a copy or a door.

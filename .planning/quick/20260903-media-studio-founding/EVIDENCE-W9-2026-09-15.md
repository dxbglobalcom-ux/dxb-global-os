## 1. THE RULE CONFLICT I HIT, AND WHAT I DID ABOUT IT

The plan's step 2 says the compiler should emit "a per-employee profile = the home department's kit + the media
group". **As the compiler stood, that is impossible without breaking a constitutional rule**, and I did not
quietly choose:

```
HOLDING_LIBRARY_SPEC A4: "applied as INTERSECTION onto the policy profile
                          (PERMISSION_MODEL G2 — library can narrow, never widen).
                          Employees ... get <slug>.employee.mcp.json overlay profiles
                          (= dept surface ∩ their union)."
PERMISSION_MODEL G2:     "... en dar kesişim geçerli."
generate-profiles.ts:    const deptManifest = profiles.find(p => p.department === emp.department);
                         ... kept = allowed.filter(tool => granted.has(tool))
```

An overlay is the intersection with the HOME department's surface. Design and marketing carry no media tool, so
the intersection is empty and the grant would have done nothing.

**What I built instead, and why it does not loosen the rule:** the assignment raises the employee's **CEILING** to
the surfaces of every department it is a *recorded member of* — home plus assigned — while the cut stays an
intersection. The employee still cannot exceed the surface of a department it belongs to. **What widened is the
MEMBERSHIP, in the org record, not the library's power over policy.** That is exactly what an assignment IS.

**And a second decision, narrower than the plan needed:** the assigned department's own grants are **not** merged
into the employee's granted set. A borrowed seat adds only what it holds BY NAME. Otherwise it would silently
inherit every tool the host department ever gains. Measured both ways before choosing — with the wide version the
two seats came out at 28 tools, identical to the narrow version today, so nothing was lost by taking the narrow road.

Both are registered: `PERMISSION_MODEL.md` **G2-bis**, `HOLDING_LIBRARY_SPEC.md` **A4**, and in the code's own header.

### ⚠ CORRECTION — THE COMMIT OF 13:55 SHIPPED OVERLAYS THAT DID NOT MATCH THE NUMBERS ABOVE

The compile output above is real and was taken at 13:52. **The files committed in `90b92611` were not those files.**
The checker session measured the committed artifact and found 23 tools, **0** `media_*`, `_generated_at`
`11:53:05.828Z`, hash `b1e5ec29` — not the 28 / `aa6aff20` this section pasted. Re-measured here by hand before
accepting the finding:

```
$ grep -c '"media_' packages/gateway/profiles/design-image-prompt-engineer.employee.mcp.json      → 0
$ grep -c '"media_' packages/gateway/profiles/marketing-short-video-editing-coach.employee.mcp.json → 0
   (23 tools each, _generated_at 2026-09-15T11:53:05.828Z, _source_hash b1e5ec29)
```

**The cause, measured.** The compiler does not only live in my script — it lives inside the resident scheduler,
which recompiles every 32 s **from its own process memory**:

```
$ systemctl --user show dxb-scheduler.service -p ExecMainStartTimestamp
ExecMainStartTimestamp=Tue 2026-09-15 08:50:43 CEST
$ stat -c '%y' packages/gateway/dist/library-profiles.js
2026-09-15 13:52:29 +0200          ← the new compiler was built 5h 2m AFTER the scheduler started
```

The scheduler had been running since 08:50 with the OLD compiler. My grant rows changed the source hash, so at
13:53:05 — **two minutes before I committed** — its next tick rewrote my correct overlays with the old
intersection (home surface only, no media). I committed the overwritten files while quoting my own earlier
measurement of the good ones. The code was right; the running process was stale; **and the record said a thing the
artifact did not carry.** That is the defect, and it is mine, not the checker's to find.

**Why "no restart needed" did NOT carry over from Part A.** Part A's change lives in the database catalogue, which
every process reads fresh — that statement was true there and is still true. Part B changed **compiled code that a
resident daemon holds in memory**. A change of that kind is not delivered until the process that holds it is
restarted. The two cases look alike from the outside and are not alike.

**The repair, in order, with the blast radius measured first:**

```
$ tasks in flight              → 0
$ media_jobs queued|running    → (0 rows)
$ pgboss jobs active|created   → 8, ALL 'created' (next-tick singletons), 0 'active' — nothing mid-execution
$ systemctl --user restart dxb-scheduler.service
ActiveState=active  SubState=running  ExecMainStartTimestamp=Tue 2026-09-15 14:01:14 CEST
$ node scripts/gateway/compile-profiles.mjs
[profiles] REWRITTEN — 22 department(s), 2 employee overlay(s), source_hash aa6aff200a39
   design-image-prompt-engineer — home design, assigned media-studio — 28 tool(s)
   marketing-short-video-editing-coach — home marketing, assigned media-studio — 28 tool(s)
```

**And then the decisive check — that the daemon does not take it back.** Waited 95 s, three recompile ticks:

```
  design-image-prompt-engineer: media_* = 5
  marketing-short-video-editing-coach: media_* = 5
  tools: 28 | generated_at 2026-09-15T12:01:22.751Z | hash aa6aff20
```

`12:01:22Z` = 14:01:22 CEST — that stamp is the **restarted** scheduler's own recompile. The running process now
carries the new compiler and produces the same result my script does. The corrected overlays are committed in the
follow-up commit named at the head of this file's § 11.

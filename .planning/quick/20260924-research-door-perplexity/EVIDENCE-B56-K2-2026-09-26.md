## 2. THE CONTRACT — shared by the three lanes; a writer implements its side exactly

### 2.1 Admissibility and the writer's rows (owner: lane A, `E`)
- `evidence.admissible(row, addr) -> tuple[bool, str]` — `addr` = the row's ADDRESS row (`address_index`). Admitted: the address
  row's `triage == "relevant"` AND (the row is a hunter quote, `tool == "evidence.py add"`, OR the address row's
  `verdict == "evidence"`). Refused with the reason: `verdict == "none"` → `avcı: kanıt değil — <verdict_reason>`; triage not relevant
  → `elendi: <triage>`; relevant, read, `verdict is None` → `hüküm yok`; no body → `gövde yok`.
- `E writer-rows <run> [--format writer|json]` — prints, for ADMITTED rows only, sorted (platform, id), the writer's line
  `[id] platform · @author · date · "passage ≤ 300" · url` (the exact line fleet.sh's inline python printed in K1; that python goes);
  stderr trailer `writer-rows: n admissible · m refused (verdict none k · hüküm yok j · elendi e · gövde yok g)`. `--format json` →
  one object per line with `id, platform, author, pub_date, passage, url, url_canonical, domain`.
- `passage_of(body)` skips CHROME: leading lines whose characters are ≥ 50 % inside `[…](…)` / `![…](…)`, or that hold ≤ 3 words;
  the passage is the first paragraph of ≥ 40 words with < 3 links; when no paragraph qualifies, today's rule. Applies at `set_body`.
  `E repassage <run>` rewrites the passage of every row whose current passage is chrome by that rule (prints `repassage: k rows`);
  a quote row of `add` (`passage` = the quote) is never touched.
- `rlib._WALL` gains `prove your humanity` and `your browser was unable to load` (two alternations, lane A's only rlib edit).
- `fetch.py`: `SCRAPLING = Path(os.environ.get("DXB_SCRAPLING") or shutil.which("scrapling") or "/home/dxb/scrapling-env/bin/scrapling")`.

### 2.2 The claim ledger — `scripts/claims.py` (owner: lane A, new) → `<run>/claims.jsonl`
A claim = every line, list item or table body row of the answer that cites ≥ 1 row after `platforms.split_paired` (table header and
separator rows never). Fields: `id` `C001…` in order of appearance · `line` (1-based) · `section` (nearest `##` above, else null) ·
`text` (the line without brackets, markdown decor stripped, ≤ 300 chars) · `kind` `verdict` (before the first `##`) | `claim` ·
`support` [ids] · `counter` [ids] · `inadmissible` [ids] (cited, refused by `admissible`; counted in nothing) · `rows` = admitted
support · `sources` · `threads` (distinct `url_canonical`) · `domains` · `counter_rows` · `counter_sources` · `thin` = `sources < 2`
(and rows ≥ 1) · `counter_status` `unchecked` | `sent` | `found` | `none` | `not-sent (cap)` | `-` (not a counter target) ·
`gap_status` the same set, `-` when not thin · `links` [{kind: against|for, id, by, at}] · `notes` [str] · `checked_by`.
- **THE PAIR RULE — one owner, `claims.sides(line) -> (support_ids, counter_ids)`:** a line with exactly one `↔` and ≥ 1 citation on
  each side of it — adjacent (`[A] ↔ [B]`) or with prose between (`… [L1533] ↔ … [L1681]`, the K1 answer's line 69) — left = support,
  right = counter; no `↔` → all support; two or more `↔` → every citation right of a `↔` and before the next `↔` is counter. render.py
  and kapsama.py read sides through this function.
- **INDEPENDENCE — `claims.source_key(row) -> str`:** `(platform, author folded)` when the author is a real name (not None / '' /
  '?' / '-' and not GENERIC = `re.I: commenter|author|user|anonymous|unknown|anon|redditor|digest|via |blog`), else `url_canonical`.
  `sources` = distinct keys among admitted support rows. Under-counts one person with two accounts; said in the page footer.
- `C extract <run> [--answer F=<run>/answer.md] [--out F=<run>/claims.jsonl] [--keep-links FROM]` — writes the ledger; with
  `--keep-links` copies `links · counter_status · gap_status · notes · checked_by` from FROM onto the claim whose `support` overlaps
  the old claim's support by ≥ 50 % (Jaccard on ids; the best match, one old → one new). Prints a table (`id | satır | kaynak |
  başlık | karşı | durum | text ≤ 60`) and `CLAIMS: n · verdict v · thin t · counter-less c · inadmissible-cited i · carried j`.
  Exit 0; exit 2 when the answer or the ledger cannot be read. `extract_claims(md: str, rows: dict[str, dict]) -> list[dict]` is the
  importable form (render.py and kapsama.py call it).
- `C list <run> --todo counter|gap [--cap 20] [--candidates 5]` — the claims a hunter works, and it WRITES the sending: counter todo
  = `counter_status unchecked` ∧ `rows ≥ 2` ∧ `counter_rows == 0`, ordered `kind` verdict first then rows desc, the first `cap` become
  `sent`, the rest `not-sent (cap)`; gap todo = `thin` ∧ `gap_status unchecked`, same order and cap. Per claim: `### C007 | rows 5 ·
  sources 4 · threads 2 · counter 0 | <text>`, then `dayanak:` lines `[id] platform · @author · date · "passage ≤ 160"`, then with
  `--candidates n` `adaylar (defterde, bağlanmamış):` up to n ADMITTED rows not on the claim whose passage shares ≥ 3 content words
  (≥ 4 letters, folded) with the claim text, same line form. Trailer `LIST: <kind> sent k · not-sent (cap) m · nothing to send`.
- `C link <run> --claim C007 (--against L1 [,L2…] | --for L3 | --none --kind counter|gap --reason "≤ 12 words") --by ROLE` —
  `--against` → links kind against, `counter_status found`; `--for` → kind for, `gap_status found`; `--none` → the status `none`
  and the reason in `notes` as `karsi: …` / `bosluk: …`. Refused, exit 2, with the reason: unknown claim · unknown id · an
  inadmissible id (`admissible`'s reason printed) · `--against` an id already in the claim's support · `--for` an id already in
  support or whose `source_key` equals one already there ("aynı kaynak: <key>"). Idempotent. Under `evidence.locked(run)`.
- `C status <run> [--format md|json]` — `claims n · verdict v · thin t · counter: todo a · sent b · found c · none d · cap e ·
  gap: todo/sent/found/none/cap · inadmissible-cited i`; json adds `owed_counter` = counter `sent` still unchecked (neither found nor
  none) and `owed_gap` the same, `new_for_links` (count of kind for). Exit 0 (1 when the file is missing).
- `C brief <run> [--ledger F=<run>/claims.draft.jsonl]` — the `{{CLAIMS}}` block for the writer's second pass: per claim
  `C007 · <text ≤ 200> · dayanak [ids] (n satır · m bağımsız kaynak · t başlık) · karşı [ids] (k) · yeni kaynak [ids] · not: tek
  kaynak | karşı arandı, yok: <reason> | karşı gönderilmedi (sınır) | kabul edilmeyen (YAZILMAZ): [ids]` — a refused id is never written by the writer (the verifier's B2, 2026-09-26).

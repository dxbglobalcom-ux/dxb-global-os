## 2. THE CONTRACT — shared by the three lanes; a writer implements its side exactly

### 2.1 Ledger fields (owner: lane A, `scripts/evidence.py`; every writer of rows sets the defaults)
| field | values | set by |
|---|---|---|
| `triage` | `pending` · `relevant` · `irrelevant` · `duplicate` · `inaccessible` | default `pending` at row birth; `inaccessible` by `fetch` when a door closes (liveness blocked/dead); the rest by `triage`/`triage-bulk` |
| `triage_reason` | string or null — REQUIRED for irrelevant / duplicate / inaccessible (refused otherwise, exit 2) | same |
| `duplicate_of` | an id or null | `triage` |
| `triage_by` | `machine` · `haiku-4-5` · a hunter role · null | same |
| `read_status` | `unread` · `partial` · `read` | ONLY `batch` and `page` (machine-printed bytes); `add` never; a declaration never |
| `read_by` / `read_at` | role / ISO time | same |
| `read_bytes` / `read_completeness` | int / float 0..1 = read_bytes ÷ bytes | same |
The row's `bytes` and body file stay as they are. `used` is not stored: `kapsama.py --answer` and `render.py` compute it from the
`[Lxxxx]` ids cited. Old runs without the fields read as `pending`/`unread` (no crash, no rewrite).

### 2.2 `evidence.py` commands (owner: lane A)
- `triage <run> --id L0001 --status S [--reason "…"] [--duplicate-of L0002] [--by WHO]` — exit 2 when S needs a reason and none given.
- `triage-bulk <run> --json FILE --by WHO` — applies `{"triage":[{"id","status","reason","duplicate_of"}]}`; prints `triaged: relevant k · irrelevant k · duplicate k · unknown-id k`.
- `batch <run> --hunter ROLE --platform P [--n 10] [--max-chars 20000]` — prints the next ≤ n rows that are `relevant` + `unread` + have a body, as
  `### <id> | @<author> | <date> | <url>` then the WHOLE body; stops before the total exceeds max-chars; a single body longer than
  max-chars is printed up to max-chars and marked `partial` with its completeness; every printed row is marked `read`/`partial`
  with read_by/read_at/read_bytes. Trailer: `BATCH: printed k · remaining relevant unread m (platform P)`; when nothing is left:
  `BATCH: nothing left — okunacak adres kalmadı`. Exit 0 both ways. Idempotent: a row printed once is not printed again.
- `page <run> --id L0001 --from BYTES [--max-chars 20000]` — the rest of a partial body from an offset; updates read_bytes; `read` when complete.
- `status <run> [--platform P] [--format md|tsv|json]` — per platform + TOTAL: `discovered · pending · relevant · irrelevant · duplicate · inaccessible │ relevant: read · partial · unread`;
  last line `RECONCILED` (discovered == pending+relevant+irrelevant+duplicate+inaccessible AND relevant == read+partial+unread) or `MISMATCH: <what>` with exit 1.
  `--format json` → `{"platforms":{"x":{...}},"total":{...},"reconciled":true}`.
- `list --unread` now means: relevant rows with `read_status` unread (the old meaning, "no body", moves to `--no-body`). Other commands unchanged.

### 2.3 `scripts/triage.py` (owner: lane A, new)
`triage.py <run> [--platform P|all] [--model claude-haiku-4-5-20251001] [--batch 60] [--dry-run FILE]` — takes rows with a body and
`triage=pending`, sends them in batches to `claude -p --tools "" --strict-mcp-config --output-format json` with the question from
`<run>/question.txt` and the triage prompt (the one measured 2026-09-26, `x-deneme-2026-09-26/prompt-triage.txt`, generalised to any
platform), parses the JSON in `result`, applies it through `triage-bulk`, prints per-batch counts and the total cost from the json
(`total_cost_usd`). `--dry-run FILE` applies a prepared JSON instead of calling the model (the tests use it). Rows without a body are
never sent to the model. Runs with cwd outside the repo (`env -C /tmp`) so no project hook fires.

### 2.4 `fleet/fleet.sh` (owner: lane B) — the controller
- RUN DIR: the first argument stays; a bare name or none → `$REPO/var/research/runs/<YYYYMMDD-HHMM>-<slug>/` (`var/` is git-ignored, on disk); a path under `/tmp` is refused with the reason unless `--allow-tmp`.
- FETCH-ALL (new step, after `from-ground`): every discovery row without a body goes through `evidence.py fetch` (`--fetch-limit N` default 400, `--fetch-workers 6`); a closed door becomes `inaccessible` with the fetcher's reason. Log: `fetch-all: tried n · bodies k · closed m`.
- TRIAGE (new step): `python3 scripts/triage.py <run> --platform all` (Haiku), then `evidence.py status` printed.
- THE HUNTER'S BRIEF (prompt): read with `evidence.py batch` and only that — a raw `cat`/`head` over `bodies/` counts nothing as read; `add` quotes from what batch printed; search further with every tool of the arsenal and `fetch`+`add` as before (his word: all the tools); keep going until batch says nothing is left or the clock; the PLATFORM line no longer carries counts (the machine prints them), it carries the HÜKÜM and the ids used.
- COMPLETION GATE (new): when a hunter returns, `evidence.py status --platform <its platforms> --format json`; if relevant unread > 0 and elapsed < 0.8·TMO → relaunch the same role with a resume prompt (`DEVAM — <m> relevant addresses unread on <p>; continue with batch`), up to `--rounds 3` (default 3); log `gate: <role> round <r> — unread <m> → relaunch | accepted | time-up`. The role's HÜKÜM is its last round's. A hunter that exits non-zero is relaunched the same way (counts as a round).
- WRITER STEP (new, default on; `--no-write` to skip): after the gate, `claude -p --model claude-opus-5-5 --effort high --tools "" --strict-mcp-config --output-format json` with `fleet/writer-prompt.md` filled: the question, every HÜKÜM line, `status --format md`, and every `relevant` row as `[id] platform · @author · date · "quote/passage" · url`; it writes `<run>/answer.md` per the recipe (the answer first; each claim line carries its `[L…]` ids; no quote text; a comparison is a table). Log the writer's cost and seconds. Then `render.py` (lane C's) → `final.html` + `final.md`.
- The end of the run prints `kapsama.py` as today. Hunters stay `claude-opus-5-5 --effort low`. The jail, allowed/denied tools, one-owner-per-platform, crowd count, merge.py, keep.sh: unchanged.

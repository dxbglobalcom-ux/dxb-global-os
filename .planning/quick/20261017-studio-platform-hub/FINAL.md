### C. The router

1. **Shot spec.** The director seat writes the shot list on its call sheet; Jev labels each shot's class and attributes (seconds, aspect, resolution, speech language, references, edit of an existing clip); Sonnet 5.5 `medium` on doubt (decision 7). No model writes a price.
2. **Candidates.** `offered` routes whose capabilities satisfy the spec.
3. **Quality gate.** score(model family, class) ≥ the class's floor. Our exam judged by his eye outranks a leaderboard row; no row means "untested", never "best".
4. **Price, in code.** Billed seconds × the unit price at that resolution, read from the catalogue at the moment the job comes — no price is a constant (his order of 2026-10-18) + billing rules (insert-video: generated seconds; recast: source length; reference tokens — R1) + conversions (kie credits, Kling units — R8), read the same way; vendor estimate endpoints where they exist (fal, WaveSpeed). Cost per keeper = price × takes-per-keeper, 1.75 (our card, 7 judged) until a route has its own.
5. **Rank.** Top band = the best score plus every route inside its published CI (AA ±15–19 at the top — R9); inside it the lowest cost per keeper, then measured speed and failure rate. A cheaper below-floor route is never chosen (COST_CONTROL A8 applied to routes); an unread price is never a number (A6).
6. **Station first.** If the station is in the top band and its queue meets the due date (625 s per 15-s take at 4 steps, ~1,150 s at 8 — capacity study), the station is the proposal and the best platform its alternative.
7. **Card.** One per job: best route per shot, total, ceiling, two alternatives (cheapest above the floor; best at any price — the L05 dial's positions), the station road, the job's cap (A5; valuable ≤ 30 % of the deal).
8. **His click → dispatch.** `control_approvals_action` releases the lines as `media_jobs` rows. A refusal or 5xx moves to the card's listed fallback inside the ceiling; past it the job stops and a new card comes.
9. **Remote lane.** Submit via `/media/<slug>`; poll (no public address, so no webhooks); download at once (Replicate keeps 1 h, Alibaba 24 h, Gemini 2 days — R8); `X-Fal-Store-IO: 0` and the shortest lifecycle on client material (R1); probe; cost row (vendor figure, else computed); event. After a restart a row with a `remote_request_id` resumes polling and never resubmits — that would pay twice.
10. **QC.** The QC seat (`personas/media-studio/media-delivery-qc.md`) verifies against the brief (AGENT_ORCHESTRATION A28); his accept/reject is F060's `decision_log` record; takes-per-keeper and refusal rate update per route.

### F. Key-catcher

- **Flow.** Arm (platform, time limit) → lock file → read the clipboard with `wl-paste -n` (works on this Wayland desk — memory note, measured 2026-10-04) → match the platform's key shape → one free authenticated read from inside the catcher → write `<SLUG>_KEY` into `vps/litellm/.env.media` (0600; ignored by `.gitignore`'s `.env.*`, measured with `git check-ignore`) → `wl-copy --clear` → recreate the proxy (a brief restart; its health check allows 60 s) → the same read through the proxy → print `slug ✓` and an 8-character SHA-256 prefix → release the lock once the session has moved the tab away.
- **Threats → answers.** Screenshot or page read while the key is visible → the hook refuses `operator shot`, browser screenshots and page reads while the lock exists · logs, process arguments → the key lives only in memory and the file; tests search every output for a canary key · repository → ignored file + gitleaks (O7) · clipboard history → cleared; whether a history extension exists is ⚠ UNVERIFIED, checked in Phase 1 · wrong content → no match, nothing stored or printed · agent environment → the key sits only in the proxy's container; the lane's virtual key stays out of SDK children (O7 allowlist, tested) · leak → he revokes on the vendor page, the flow repeats.
- **Why no model sees it.** No model is in the path; the proxy injects the header server-side (`set_env_variables_in_header`, measured in LiteLLM 1.97.0); models see only a check mark and a fingerprint.
- **⚠ UNVERIFIED:** whether repeated `wl-paste` reads take focus on GNOME; Phase 1 measures it with the browser focused; fallback is an XWayland read.

### H. LiteLLM — measured, decided

Summary
-------

Fixes [#8020](https://github.com/maplibre/maplibre-gl-js/issues/8020).

Default `draggable: true` markers:

* get a managed `tabindex="0"`; a `tabindex` supplied by the application is never added to, changed, or removed
* move with the arrow keys while focused: 1 screen pixel per press, 10 with Shift
* fire the same gesture as pointer dragging: the position updates first, `dragstart` fires once on the first movement, `drag` fires per movement (key repeats included), and `dragend` fires when the key is released or the marker loses focus
* do not also pan or rotate the map: the handled keydown is stopped before the map's `KeyboardHandler` (which listens on the canvas container the marker lives in) can see it
* keep the managed `tabindex` while either dragging or an attached popup keeps the marker interactive

Markers created with a custom `element` are left completely alone; focusability and keyboard behavior stay application-owned, per the discussion in [#7790](https://github.com/maplibre/maplibre-gl-js/issues/7790). Alt/Ctrl/Meta arrow combos and keys coming from elements nested inside the marker are also left to the browser and application.

[#8022](https://github.com/maplibre/maplibre-gl-js/pull/8022) is open for the same issue. The behavior differences at this point: this PR supports Shift for a 10 px step and treats a held key as a single drag gesture (`dragend` on release), while [#8022](https://github.com/maplibre/maplibre-gl-js/pull/8022) moves 1 px per unmodified press and fires a complete `dragstart`/`drag`/`dragend` cycle per press. Fine closing or adapting this one if maintainers prefer that direction.

* Tab reaches the marker right after the map canvas; the focus ring is visible
* one ArrowRight moved the marker element exactly +1.0 screen px (bounding rect x: 436.5 to 437.5) with the camera not moving at all (measured 700 ms after the press to catch any easing)
* a mixed sequence (3x ArrowRight, 2x Shift+ArrowRight, 2x Shift+ArrowDown, 1x ArrowDown) landed at exactly +23 px / +21 px, with no camera pan or rotation mixed into the result
* the example's `dragend` handler updates the coordinates readout on key release

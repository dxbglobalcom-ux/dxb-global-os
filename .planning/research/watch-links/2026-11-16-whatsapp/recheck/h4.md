## w071: Skills Manager (shenysun/skills-manager), a CLI that keeps one skill library for many agents, plus an offline skill-routing quality gate
- **Opened:** the X post and all its replies (`opencli twitter thread … -f yaml`), gh api metadata, `git clone --depth 1` at 948db52 (v2026.11.4), README.md read in full, and the source of `src/core/services/description-lint.ts`, `description-overlap.ts`, `trigger-rank.ts` (head), `security-scan.ts` (rules) and `cost-ledger-service.ts` (method). I did not read docs/CLI.md, the manager SKILL.md (354 lines) or the dashboard. I did not install or run the npm package.
- **What is in it:** MIT, 243★, 6 forks, created 2026-08-26, last push 2026-11-04, TypeScript. It keeps one hub (`~/.skills-manager`) and distributes skills to 70+ agent runtime dirs by symlink or copy. It takes skills from five source types (git, URL, zip, Claude plugin marketplace, well-known index). Its update check uses the git tree-SHA of the skill's own subfolder. `cost` is a resident-context ledger (chars/4, CJK ×1). It also does provenance backfill, category sets (load only some domains per agent), and hub git sync. The old reading missed a whole family of features, the **skill-routing CI gates**, which are offline and need no model:
  - `audit descriptions`: lints each description for missing, >1024 chars, XML tag, name format, **no "Use when…" trigger clause**, first/second person, and vague (<40 chars or <4 distinctive terms). Each finding comes with a fix line (`description-lint.ts:33-54`).
  - `audit overlap`: an IDF-weighted Jaccard between each pair of descriptions finds two skills that compete for the same request, and suggests a boundary sentence (`description-overlap.ts:53-91`, default threshold 0.3).
  - `trigger test "<request>" --expect <skill>`: ranks every skill against a sample phrasing and fails CI if the expected skill is not #1. A fixtures file holds many cases.
  - `audit security --strict`: a regex scan of a skill tree for `bash -c`, child_process, subprocess, curl/wget/fetch, `~/.ssh`, `.aws/credentials`, `.env`, AWS/OpenAI key shapes and private keys (`security-scan.ts:38-56`). It is report-only, with no prompt-injection patterns.
  - The X replies add two things. A reply named "skill-freshness" (missing CLIs, copies behind upstream, skills now native). The author also said, in reply: *"a skill prompt can't enforce that boundary"* (permissions over prompts).

## w056: OpenMausBot (milind-soni/OpenMausBot), a chat app where each "bot" is a local claude/codex/grok CLI agent, with a harness server, permission broker, routing model, triggers and portable team packages
- **Opened:** gh api metadata, contributors and recent commits; `git clone --depth 1` at b832de7 (v0.1.169, 2026-11-18 00:31 +0530); README.md read in full; `docs/decision-model.md` lines 1-80; `docs/approval-levels.md` lines 1-60; `evals/README.md`; the Claude driver's result handling `server/drivers/claude.ts:1582-1625`. I also read the separate repo `milind-soni/openmausbot-teams` (FORMAT.md and one playbook's structure). I did not build or run the app, and did not read the 8,668 files beyond these.
- **What is in it:**
  - **The project:** Apache-2.0 except `enterprise/`. 24,720★, 3,466 forks, 1,158 open issues. Created 2026-08-11, pushed 2026-11-17.
  - **Real activity, not hollow:** 271 contributors (top: milind-soni 6,611 commits, then 783 / 716 / 345). 100 commits landed between 12:15 and 19:01 UTC today. PR numbers have reached #6440. The old note's "star inflation possible" is answered by the activity, though stars themselves were not audited.
  - **Architecture:** a harness server on 127.0.0.1 owns every agent process. It normalizes Claude stream-JSON, Codex JSON-RPC and ACP into one canonical event stream (NDJSON per thread), sent to the UI over one SSE stream. A driver SPI adds a provider with one file.
- **Parts examined:**
  - **Result-error classification:** in `server/drivers/claude.ts:1587-1619`, `ok = o.is_error !== true`, regardless of `subtype`. An error result's reason comes from `terminal_reason` or a non-success `subtype`, never from `stop_reason` (comment at 1609-1610). It separates `auth_required`, `quota` (usage limit) and `update_required`. A `--resume` refused after long idle ("No conversation found with session ID …") closes the session so it rebuilds once.
  - **Approval levels per bot** (`docs/approval-levels.md`): Ask / Auto-accept edits / Approve for me / Full access, each mapped to the provider's own permission mode.
    - It can be changed mid-turn.
    - A handed-on job uses the *receiving* bot's level, except from the Chief of Staff, whose level flows down.
    - Sends through connected apps (email, posts, payments) have a separate "Sending on your behalf" setting.
    - A bot reading its own files (SOUL.md, skills, memory) never asks, but only for a plain read command with no pipe, redirect or variable.
  - **Decision model** (`docs/decision-model.md`): a fast classifier (Cloudflare Workers AI free tier, TypeSafe Jev, an OpenRouter decisions model, or a custom endpoint) picks which bot answers an un-addressed message in a few hundred ms. Its threshold is 0.6, "measured against" Jev's calibrated probabilities. It **fails open to the room's lead** when it is off or unsure. It never does the work itself.
  - **Behaviour evals** (`evals/README.md`): "evaluate the harness, never the models". A scripted engine replays deterministic turns with no API calls. There is a golden-thread replay (a real thread is redacted with a leak scan and replayed against committed trace baselines), and a `tool-choice` set of real requests that went wrong, in the words people used.
  - **Triggers:** schedules every 5-1,440 min that **skip an occurrence when the previous run is still active** ("so slow work cannot build an unbounded queue"). A webhook secret is never shown to the bot.
  - **Its MCP server** is deliberately bounded: no approval grants, deletion, credentials or computer lifecycle.
  - **Voice:** "markdown is rewritten into something worth hearing before it is spoken", and calls narrate what the bot is doing and ask approvals out loud.
  - **Team packages** (`openmausbot-teams`, MIT, 99★, pushed today): one Markdown file per team, with YAML frontmatter (`agents`, `rooms`, `routines`, `playbooks`) and required body sections Activation / Mission / Outcomes / Connections / Team / Chief of Staff / Completion rule. Routines must be `enabledAfterInstall: false`, and packages never carry credentials, memory or connections. There are six teams (100x-marketing, competitor-watch, engineering, inbox-follow-up, reddit-lead-miner, seo-growth). `reddit-lead-miner` scores public conversations by "ICP fit, problem strength, intent, timing, and confidence" and drafts outreach under the rules "Never invent familiarity, results, customer proof, urgency, or scarcity. Draft only; never post or send without the user's explicit approval". An optional `proof` block for money claims requires a public source link and "never restate someone's claim as a bigger or rounder number".

  - **B65 is still open and confirmed today.** `packages/orchestrator/src/chat-drain.ts:168` checks only `msg.subtype !== "success"`. `grep -rln is_error packages --include=*.ts` (excluding dist and node_modules) returns **nothing**.

- **What is in it:** MIT, 5,196★, 679 forks, created 2026-08-22, pushed 2026-11-17. The README's own notice says the extension "observes and automates the ChatGPT browser UI … not a public ChatGPT automation API", and that it "cannot guarantee … protection from account warnings, restrictions or suspension". The parts examined:
  - **Compact & Resume brief prompt** (`src/shared/handoff.ts:11-40`):
    - The user's messages are "the highest-authority source … the specification".
    - Every requirement and later correction is kept, and unfinished requirements matter most.
    - "An assistant message saying it will do something is not evidence that it happened; a recorded tool call that succeeded is. Say plainly which is which."
    - Exact identifiers are kept, and the failure → root cause → change → verification chain is kept together.
    - "lossless operational compression, not an executive summary".
    - Headings: TASK / USER SPECIFICATION / CURRENT STATE / DONE / IN PROGRESS / PLANNED-DECIDED / FAILED-UNRESOLVED / FILES / VERIFICATION / ENVIRONMENT / NEXT / **DO NOT** (what the next agent should not redo or undo).
  - **Goal step reviewer** (`src/main/goal-review.ts:62-91`): after each Goal step that edited files, a worker reviews the step's net diffs. It may run tests but may not edit or delegate. It reports "real problems … with file and line", answers exactly "No problems found." when there are none, and starts with "BLOCKING:" only for data loss, a broken build, or a security problem. It states plainly that "files changed by commands are not listed". Its brief is capped at 24k chars, and diffs that do not fit are named.
  - **Goal completion protocol** (`goal-templates.ts:2`): the last line is exactly `[[COS_GOAL:COMPLETE]]` or `[[COS_GOAL:CONTINUE]]`, followed by "Do not claim completion for partial work. If user input is required, explain it and omit both markers". A missing marker pauses the loop, and provider errors stay errors, not completion (`astra-goal-loop` doc). The rotated continuation phrasings (60 variants) are specific to the ChatGPT UI.
  - **Stuck notice** (`src/main/stuck-notice.ts:1-11`): measured "24 + 53 + 76 minutes of standstill, every one of them ended by the user happening to glance at the app". The fix is a notification, deliberately *not* a message invented and sent under the user's name.
  - **Other features:**
    - "Step for you": the exact command, folder and expected output, run by the human and marked done.
    - Phone via ntfy or your own Telegram bot (`/status`, stop, pause, deny), with **"Nothing can be allowed remotely"**.
    - A "why stuck" row (since when, how many tries, each step, amber when it gave up).
    - Related folders that give context without widening access.
    - A limit on how many chats run at once.
- **What we have:**

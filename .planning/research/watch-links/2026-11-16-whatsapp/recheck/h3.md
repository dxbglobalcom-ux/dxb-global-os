## w067 — Kanzo: one-binary local kanban + MCP server shared by a human and coding agents (CEO's "kanzo v3" = v0.3.0, 2026-11-01)
- Opened: X post via `opencli twitter thread … -f yaml` (post + 49 replies, saved `h3/thread.yaml`); the post image (README screenshot, read); `gh api repos/emanuele-em/kanzo`; README (whole); releases list; file tree; source `src/mcp.rs` (886 lines, read the tool layer), `src/store.rs` (grep), `src/schema.sql`, `CHANGELOG.md`. Not done: not installed or run.
- What is in it:
  - 1,226 stars, 98 forks, AGPL-3.0, Rust, created 2026-10-25, pushed 2026-11-17; 11 releases v0.1.0 (2026-10-26) → v0.4.2 (2026-11-11). His "v3": the author's reply in the thread — "v0.3 came out today: one machine can share its board and the others join it" (v0.3.0 published 2026-11-01T20:21Z).
  - Board in the browser (localhost:4242) + MCP server (`kanzo mcp` stdio or `/mcp` HTTP) on one SQLite file. 10 MCP tools: list_projects, create_project, link_repo, list_tasks, get_task, create_task, update_task, add_comment, **next_task** ("take the top todo task, move it to doing and show it"), delete_task.
  - Server instructions sent to every agent (mcp.rs lines 40-42): "Keep it current unasked: doing when you start a task, comments on what you did, review when you finish or get stuck, url for a PR you opened. **On review, comment how to resume this session.** Leave done and human tasks to the user."
  - **Token economy is designed in:** tool schemas stripped of `$schema` and null types "because agents read this list in every session, so each byte counts" (mcp.rs 286-307); replies are short plain text; README claims tool list ≈1,000 tokens once, replies 10-60 tokens (measured on an Apple M4 — the author's number, not mine).
  - `human` flag: human tasks are hidden from `list_tasks` for agents ("N human tasks not shown") and skipped by `next_task` (`t.human = 0`, store.rs 915). `waits_on`: next_task skips a task until its blockers are `done` and says "Nothing ready… N tasks wait on others". GitHub-style filter language shared by board and agents (`tag:`, `status:`, `is:human`, `is:waiting`, `-` negation).
  - Liveness: every write bumps one `changes` counter by trigger, the board polls it, so agent moves appear live (schema.sql).
  - Backlog column "agents leave alone" is **a convention, not enforced**: `update_task` (mcp.rs 497-524) moves any task to any status with no backlog or human check — confirmed in code; a reply in the thread asked for exactly this ("make that a permission the MCP server enforces"). Sharing has **no login** ("share only on a network you trust").
- What we have: `packages/dxb-mcp/src/groups/queue.ts` — queue_create_task, queue_dispatch (plan → one task per seat with dependencies), queue_claim (atomic SKIP LOCKED lease, refuses an employee as claimer), queue_transition, queue_return (with feedback), queue_get, queue_list, queue_sheet_times; `task_dependencies` table; the approval gate for human stops. So next_task / waits_on / human-task already exist in a stronger, enforced form. Construction sessions use the markdown board (`00-BOARD-OPEN-WORK.md`), not an MCP board. No Kanzo mention in the repo.
- What it has that we do not:
  1. **Reply thrift:** our `ok()` returns `JSON.stringify(data)` of the whole row (`queue.ts:26`; queue_claim returns `SELECT * FROM claim_next_task(...)`), Kanzo returns a one-line text summary. I did not measure our reply or tool-list size in tokens — UNVERIFIED how much we would save.
  2. **"On review, comment how to resume this session"** — a resume pointer written by the agent into the task. Not found in our queue tools (grep not exhaustive across Hamza; UNVERIFIED for the runtime).
  3. **One filter language** shared by the CEO's screen and the agents' tool.
  4. A **"nothing ready because N wait on others"** answer instead of a bare empty result.
- Possible use for the holding:
  - **dxb-mcp / B85 foundation (small, concrete):** take three things into our MCP: compact text replies + stripped schemas, the resume-pointer comment on hand-back, the "why nothing is ready" answer. First trial: measure the token size of our 28 tools' list and of one queue_claim reply, then the same with a compact text reply.
  - **B32 (screen idea):** the board's look is the anti-pattern he rejected ("task manager"), but two pieces fit the living-surface law: agent comments streaming onto the card as it works, and a dimmed card that says what it waits on.
  - **B84:** not offerable to clients — no login on share, single-user local tool.
  - Not as a second board for our sessions ("the plan exists once").
- The old reason: **partly** — right that we do not install it as a board, but the old row read only the README and called it "a separate developer tool"; the code shows three cheap, concrete improvements for our own MCP, and confirms (not guesses) that its backlog rule is unenforced.

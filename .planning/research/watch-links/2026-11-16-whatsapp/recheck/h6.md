- **What is in it (from the old row):** a marketer has Claude Code run `/loop` over a website one page at a time. Each page is analysed for SEO on three axes: technical, text and tracking. A change log for that page is saved as a PDF, the page is marked done, and the loop moves to the next page. The claim is that working page by page gives better results than one pass over the whole site. The reel shows no tool, measurement or result.
- **The method written as a Web Studio (B84) service, "Page-by-page SEO pass":**
  1. *Inventory.* Crawl the client site to get the URL list. Use free Frog for up to 500 addresses and paid Frog or LibreCrawl above that (B84.md:89,92). Write the list as a queue file, one row per URL with status `todo`. Order it by value: money pages first, using Search Console clicks when the client grants access.
  2. *One page per loop turn.* Pick the first `todo` row and run three checks.
     - Technical: status, canonical, index directives, title and meta, headings, schema (the schema gate), links (lychee), speed (Lighthouse/Unlighthouse) and accessibility (axe/Pa11y). All of these are already named as core in B84.md:89.
     - Content: the searcher's intent for the page's query against the leading results, and whether the page answers it specifically. This is the per-page test in OpenSEO seo-audit/SKILL.md:51.
     - Tracking: GA4/GSC/Clarity tags present and firing.
  3. *Change log per page.* Record what was found, what was changed or proposed, and the evidence with its date. Every SEO figure is marked measured or estimated, with source and date (B84.md:95). Deliver as HTML that prints to PDF, as `seo-report` already does (seo-report/SKILL.md:10).
  4. *Mark the row done* and take the next row. Add a stop condition: the queue is empty, or a page/token budget is reached. The old row's note is right that an open-ended `/loop` burns quota.
  5. *Close with a site summary.* Run OpenSEO `seo-audit` over the finished logs to pick the 1-3 changes that matter most.

  Sold as: a one-off "every page checked" audit, plus a monthly pass over new or changed pages inside the "SEO and content" monthly package that B84 already names (B84.md:63). I have no price; none is invented.

- **The two the old row named as missing — what taking them would look like here and what it costs:**
  - **Worktree isolation.**
    - What it would be: Claude Code already ships it, so nothing needs to be built. The installed 2.1.326 binary carries `` `isolation: "worktree"` gives the agent its own git worktree (auto-cleaned if unchanged)``. Its own system text says "When dispatching two or more agents that will write or edit files in the same repository, give EACH `isolation: "worktree"`" (grep of `/home/dxb/.local/share/claude/versions/2.1.326`). Taking it means one line in `dxb-team3` §3: parallel `helper-writer`s are opened with `isolation: "worktree"`, and the lead merges each branch after verifying it. Plus one setting, `worktree.baseRef: "head"`. That setting is mandatory: the default `fresh` branches from `origin/<default>` (CHANGELOG line 7527), and `master` is **475 commits ahead of `origin/master`** (`git rev-list --count origin/master..master` = 475). Writers would otherwise start on a months-old tree.
    - Measured frictions:
      - `node_modules` is 1.1 GB (`du -sh`) and is not in a worktree. Each worktree needs `pnpm install` or a link. UNVERIFIED which one Claude Code does; `sparsePaths` exists (CHANGELOG lines 427, 8773).
      - The 3 untracked `.env*` files at the repo root are absent in a worktree. Their names were counted, nothing was read. The construction DB URL comes from `.claude/settings.json` env, so tests may still reach the engine.
      - The database is NOT isolated by a worktree. There is one construction engine on port 54422, and `DXB_ENGINE_LOCK_WAIT` still serializes the test runs.

    - Gain: parallel writers cannot overwrite each other or a peer session's uncommitted work. The tree has 1,047 porcelain entries now, so sessions share a dirty tree. Step 7's rollback also becomes a cheap `git worktree remove --force`.
    - **It reopens his 2026-10-28 "not taken"** (ceo-approvals.json:2949) and changes a door, so it is his word (`.planning/quick/20261014-88-link/MERGE.md:105`: "a door change — his word").
  - **Signed receipts.**
    - What it would be: `scripts/construction/battery.sh` ends by writing `.git/dxb-receipts/<tree>.json`, holding the `git write-tree` hash of the tested index, both suites' exit codes, the time and `BATTERY_GREEN`. `pre-commit` adds a class: when code is staged, it compares `git write-tree` with a receipt and stops without one, with a `DXB_SKIP_…` escape like the hook's others.
    - Two corrections to the post's design:
      - The receipt cannot hold the *commit SHA* and be checked in pre-commit, because the commit does not exist yet. The tree hash is the workable key.
      - A cryptographic signature adds nothing here. The same agent that runs the battery can run `ssh-keygen -Y sign`; sessions run in `bypassPermissions` (`~/.claude/settings.json` and `.claude/settings.local.json`); there is one machine and one key. A hash-bound receipt gives the practical guarantee. A signature only matters if the key sits behind a process the agent cannot reach.
    - Cost:
      - Every code commit waits on a battery of the exact staged tree, about 6 minutes for 1,486 tests (`dxb-team3/SKILL.md:286`, measured 2026-10-04).
      - A fix after Sol re-runs it. That is already the rule (`:281-282`), so this mostly mechanizes it.
      - The light lane (`easy-writer`, no battery) needs an exemption or gets slower.
      - Two sessions on one index will often see a tree mismatch.
      - Writing it is a small script plus a hook block. Hours, not days, by my estimate (UNVERIFIED).

## 3. Capabilities — the mechanism this source shows

**1 — A command layer that is an employee, not a menu `T` `V`.** *"Agent one is my CEO. Every single
morning at 6am it reviews what got done yesterday, decides what matters today, and then assigns work
to the rest of the team."* Its card states its job in one sentence and counts its own work —
`ROUTES 169`, `READS 288`. The hierarchy is drawn: one card on top, tree lines down to five.

**2 — Five specialists, each a role with a printed brain `V`.** Researcher · CMO · Sales Rep · Dev ·
Data Analyst, each with a layer name, a one-line job, a live state and **the model it runs on
printed on its own card** — and the models are **mixed by role**, two on `gemini-2.5-pro` and four on
`gpt-5.5`. The owner can see which employee thinks with which brain without opening a setting.

**3 — Every employee is a conversation, and the conversation has an address `V`.** `#ceo-channel`,
`Command layer`. The chat is not one box for the whole system; it is **one channel per employee**,
reachable from the command centre with the employee's live state still on the chip.

**4 — The machine reports on itself beside the work `V`.** Integrity, agent calls, messages, tokens
in and errors on one row; CPU, RAM, disk and database size on the next; and a **security posture
block whose four rows each open a config** — mission-control exposure, SSH, firewall, local data
permissions. Governance is on the same screen as the work rather than in a separate section.

**5 — The context window is a visible object `V`.** A panel names an agent, its task count, its last
status line in plain words, and draws how full its context is as a segmented bar. **How much room an
employee has left to think is something the owner can see.**

**6 — The shared memory is the product's own claim, and it is drawn `T` `V`.** *"The real unlock is
the shared knowledge memory system. Every single agent can see what every other agent learned,
finished, and flagged."* On screen: 53 indexed nodes, **226 relationships**, 214 tracked, 37
visualised artifacts, one search box across agents, memories, notes, topics and paths, and a node
inspector that gives a memory's **type, age, size, link count, file path and tags**. Agents,
memories, documents, data artifacts, config files and topic hubs are all nodes in **one** graph —
the employee and the thing it learned live in the same picture.

**On what this source PRODUCES:** the recording **does not show revenue** — no euro, no dollar, no
customer count. What it does show is **use**: 11,164 messages, 218 agent calls, 26.5 million tokens
consumed, 10 errors, a memory graph 18 hours fresh, and a lead pipeline carrying real names with
real call times. `U` Whether it earns is not on the film; that it runs is.

### Aliveness — how this source is built to live, and what DXB takes

**What runs on its own clock `T`:** *"Every single morning at 6am"* — the command employee wakes
itself, reviews yesterday, decides today's priorities, and hands work out. He states the outcome as
**"zero manual task management"**: the owner does not queue anything. A second clock is visible in
the vault, where a node reads **`18H AGO`** and another is named `Daily KB Sync` — the memory is
refreshed on a schedule of its own.

**What makes the surface breathe — measured against a static control.** The left navigation was used
as the control because it carries no live data. Over the same frames:

**So the surface has two speeds of life, and they are deliberate.** The identity object — the orb in
the agent's channel — moves 96 times more than a static region. The knowledge graph moves 8 times
more: continuous, gentle, never still, never busy. And **everything else is genuinely still**:
across all 798 frames, outside the 25 page transitions the whole screen changes by a mean of
**0.96**, and the navigation by **0.06**. The stillness is what makes the two moving things read.

**How it answers the human:** the page changes are the owner's own clicks, and they are **short** —
of 25 measured transitions the longest is **2.7 s** and most are **0.1–1.0 s**. The interface does
not animate between pages; it arrives.

**What DXB takes:**
1. **The three-state pill on every page, with a neutral idle.** Our 205 employees have one state and
   it is `dormant`; his have three and the resting one is not an alarm. This is our first law made
   concrete — *motion IS state, and rest is part of the design*.
2. **The command layer raised by brightness, with its own counters on its own card.** `ROUTES` and
   `READS` on the orchestrator is the smallest honest way to show that a brain is working.
3. **The model printed on the employee's card.** We already store a brain per employee (measured:
   183 on `claude-sonnet-5`, 22 on `fable-5`) and show it nowhere.
4. **One graph holding employees, memories, documents and config together, with a node inspector.**
   This is exactly the memory brain the CEO approved on 2026-08-01 (`v2-memory-brain-2026-08-01`) <!-- CEO-OK: v2-memory-brain-2026-08-01 -->
   and this source is the first on the queue to show one working, with its counters and its inspector.
5. **The context window as a visible object.** Nothing in our product tells the CEO how full an
   employee's head is.

On 2026-07-06 I told the CEO an Obsidian sidebar fix was "done" (symlink to .planning) without any test. It did not work — Obsidian doesn't index symlinks to hidden targets. The CEO's hardest feedback of the project: "olmamış şeyi tamam diyorsun — en nefret ettiğim şey" (you call unfinished things done — the thing I hate most).

**Why:** As sole human, the CEO cannot clean up after me. One false "done" poisons trust in every other "done" — in an autonomous company OS, verified completion claims are the entire product.

**How to apply:**
- Report "done" ONLY with the executed verification command + decisive output. Otherwise report status honestly as in-progress/unverified.
- Anything I cannot observe from the terminal (GUI rendering, external dashboards, third-party state) is NEVER "done" — label `⚠ UNVERIFIED — needs human eye`, separated from verified items.
- "Should work / will appear" = hypothesis; only tested outcomes get past tense.
- Binding rule also written into project CLAUDE.md ("Evidence-Before-Done" section). Related: [[model-routing-hierarchy]].
- CEO also demands full self-service: do everything myself, never hand him task steps unless only a human can do it (sudo password was volunteered for this; rotate with CRED-21).

## Header rules — read before filling any row

- **No secret values.** This file records status codes, error phrases, and UTC timestamps only. Never write an old or new password, key, or token value here, even partially.
- **Probe-before-tick rule.** A row's **DEAD?** column may be marked complete (✅) only when that row's **Probe (UTC)** cell AND its **Observed** cell are both filled. Ticking without probing is structurally impossible if this rule is followed — do not write ✅ into an empty row.
- **Observed column contract.** The **Observed** cell may hold only a status/error code (e.g. `401`, `403`, `535-5.7.8`) or the literal phrase `login rejected`. Never a response body, never a value.
- **N/A rows.** Rows that genuinely do not apply put the literal `N/A (reason)` in the **DEAD?** column itself — e.g. `N/A (local software)`, `N/A (not in leaked doc)`. Any fuller explanation goes in the **Action** column instead. Plan 01-04's completeness gate parses the **DEAD?** column specifically (cross-AI review HIGH-2) — writing `N/A` anywhere else (Action, Notes, Observed) does NOT resolve a row; the gate will still see it as incomplete.
- **CRED-17 (Apify) grace field — special case.** The row's **Action** cell is pre-filled with the placeholder `grace=__PENDING__`. Replace it with exactly `grace=declined` (immediate invalidation chosen) or `grace=accepted; probe_after_24h=yes` (24h grace window accepted, delayed probe scheduled). Plan 01-04's gate parses this cell by column — Action only, never a whole-row grep — and blocks while the placeholder text remains (cross-AI review MED-2). This instruction lives here, in the header, and nowhere inside the row itself, so an untouched template cannot accidentally satisfy the gate.
- **Uniqueness.** Every new value entered during this rotation must be unique per service, generated by a password manager — see ATT-01 below. No password may be reused across two services; password reuse is the root-cause hazard this phase remediates.
- **ID set.** The ID column below is pre-assigned exactly CRED-01 through CRED-21, each appearing exactly once. Do not add, remove, renumber, or duplicate rows — plans 01-04 and 01-06 re-prove this exact set with a sorted-ID-set gate (cycle 3 MED-6).

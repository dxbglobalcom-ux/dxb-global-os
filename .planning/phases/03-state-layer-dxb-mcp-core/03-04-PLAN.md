<implementation_notes>
- SDK 1.29: use `McpServer` + `registerTool` (Zod raw-shape inputs) + `StdioServerTransport`. Server name `dxb-mcp`, version `0.1.0`.
- Tool naming: MCP tool names may not contain dots in some clients — register as `queue_create_task`, `queue_claim`, ... (underscore form) while keeping the master-plan's dotted names as the documented logical names; note the mapping in code comments once at the registry point.
- Tests run the server IN-PROCESS via `InMemoryTransport.createLinkedPair()` from the SDK (real protocol, no subprocess) against the running local stack (03-02). Tests reset state via `supabase db reset` in a beforeAll (or truncate tasks/task_events between tests — choose one, record it).
- Transition table (transitions.ts, LOCKED from master-plan): inbox→queued; claimed→running; running→review|failed; review→awaiting_approval|done|returned; awaiting_approval→done|failed; returned→queued. `queue.transition` consults ONLY this table; `returned` requires non-empty feedback and writes it to tasks.feedback.
- Every mutating tool appends task_events (where task-scoped) AND audit_log (always) in the same transaction as the mutation — kysely transaction API.
</implementation_notes>
